# Stellar Burgers API Tests

Набор интеграционных API-тестов для учебного сервиса Stellar Burgers. Проект проверяет создание пользователя, авторизацию и создание заказа, использует `pytest`, `requests` и Allure-разметку.

## Покрытие

- создание уникального пользователя;
- запрет повторной регистрации с теми же данными;
- обязательность `email`, `password` и `name`;
- успешная и неуспешная авторизация;
- создание заказа с авторизацией и без неё;
- создание заказа с несколькими ингредиентами;
- обработка пустого списка и неверного идентификатора ингредиента.

Всего: 10 тестовых функций и 12 тест-кейсов с учётом параметризации.

## Структура

```text
.
├── .github/workflows/ci.yml  # безопасные проверки pull request
├── src/
│   ├── api.py                # API-клиент
│   └── config.py             # URL и HTTP timeout
├── tests/
│   ├── conftest.py           # setup/teardown fixtures
│   ├── test_create_order.py
│   ├── test_create_user.py
│   └── test_login_user.py
├── data.py                   # ожидаемые ответы и тестовые константы
├── helpers.py                # генерация данных и вспомогательные шаги
└── requirements.txt
```

## Требования

- Python 3.12;
- доступ к учебному API Stellar Burgers;
- Allure CLI — только если нужен локальный HTML-отчёт.

## Установка

```bash
python -m venv .venv
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

После создания окружения активируйте его способом, принятым в вашей операционной системе.

## Конфигурация

Настройки читаются из переменных окружения и имеют безопасные значения по умолчанию:

| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| `STELLAR_BURGERS_BASE_URL` | `https://stellarburgers.education-services.ru` | Адрес учебного API |
| `STELLAR_BURGERS_HTTP_TIMEOUT_SECONDS` | `10` | Максимальное ожидание HTTP-запроса в секундах |

Пример значений находится в `.env.example`. Файл `.env` проект автоматически не загружает и в Git не включает.

## Безопасная локальная проверка

Эти команды не выполняют API-запросы:

```bash
python -m compileall -q src tests data.py helpers.py
python -B -m pytest --collect-only -q -p no:cacheprovider
```

Ожидаемый результат сбора — 12 тестов.

## Полный интеграционный запуск

```bash
python -B -m pytest -q --alluredir=allure_results
```

Полный запуск обращается к внешнему учебному сервису: создаёт тестовых пользователей и заказы. Пользователи удаляются в teardown fixtures, но заказы могут сохраняться на стороне сервиса. Запускайте команду осознанно и только когда такое использование сервиса разрешено.

Для просмотра локального Allure-отчёта:

```bash
allure serve allure_results
```

Каталоги с результатами и отчётами Allure являются generated-артефактами и не должны попадать в Git.

## CI

Workflow для pull request устанавливает зависимости, компилирует Python-файлы и выполняет только `pytest --collect-only`. Автоматический интеграционный прогон намеренно не настроен, чтобы PR-проверки не изменяли состояние внешнего сервиса.

## Работа с чувствительными данными

Тестовые email и пароли генерируются отдельно для каждого запуска. Токены используются только в памяти процесса и не записываются в исходный код или репозиторий.
